# Fixtures

Sample projects, keystores and bundles the tests read. Nothing here is built: the files exist to be
parsed. Demo mode uses `fjord-notes`, the fictional project from `design/`.

| Fixture | What it is for |
| --- | --- |
| `fjord-notes/` | The demo project, `app.fjord.notes`. Kotlin DSL, version catalog, flavors, three deliberate findings |
| `groovy-app/` | Groovy DSL, no version catalog, passwords read from the environment |
| `not-a-gradle-project/` | A folder that is not a Gradle project |

## Keystores

`fjord-notes/keystores/` holds keystores generated by `keytool` for these tests only. The private keys are
worthless: they sign nothing that exists and the passwords are in this repository on purpose, because the
tests need to open them.

| File | Format | Alias | Password | Key | Certificate |
| --- | --- | --- | --- | --- | --- |
| `debug.keystore` | JKS | `androiddebugkey` | `android` | RSA 2048 | valid 2024 to 2053, the shape Android Studio generates |
| `release.jks` | JKS | `upload` | `fjord-release-2024` | RSA 4096 | 30 years, stands in for an upload key |
| `legacy.p12` | PKCS12 | `legacy-key` | `fjord-legacy` | EC P-256 | ~13 months, so the short-validity warning has something to fire on |

`fjord-notes/app/google-services.json` registers the real SHA-1 of `debug.keystore` and of `release.jks`,
and deliberately does not register a Play app signing certificate. That absence is the Signing tool's
headline finding and the thing the fingerprint matrix has to show as missing.

Regenerating a keystore changes its fingerprints, so `google-services.json` has to be regenerated with it
or the fixture stops being self-consistent. Tests read the fingerprints from the keystores rather than
hard-coding them, except where a test is specifically about the comparison.
